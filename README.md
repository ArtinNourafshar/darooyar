# دارویار 🩺 | Darooyar

**یادآور دارو و وعدهٔ غذایی خانوادگی + دستیار سلامت — فارسی، راست‌چین و بدون سرور**

![Flutter](https://img.shields.io/badge/Flutter-3.x-02569B?logo=flutter&logoColor=white)
![Platforms](https://img.shields.io/badge/platform-Windows%20%7C%20Android-333?logo=windows&logoColor=white)
![Tests](https://img.shields.io/badge/tests-70%20passed-4c1?logo=pytest&logoColor=white)
![Offline](https://img.shields.io/badge/data-local%20SQLite-007EC6?logo=sqlite&logoColor=white)

دارویار یک اپلیکیشن **فلاتر** برای یادآوری مصرف دارو و وعده‌های غذایی اعضای خانواده است؛ با تمرکز بر سالمندان و خانواده‌هایی که چند داروی زمان‌بندی‌شده دارند. همهٔ داده‌ها **به‌صورت محلی** (SQLite) ذخیره می‌شوند، رابط کاربری **فارسی و راست‌چین** است و **اینترنت فقط و فقط با فعال‌سازی اختیاری دستیار هوشمند** استفاده می‌شود.

> **English:** Darooyar is a Persian, RTL family medication & meal reminder with health tracking, water intake, backup/restore and an opt-in built-in Grok AI assistant for Windows and Android. All data stays in a local SQLite database — no account, no server; internet is used only if you explicitly enable the AI assistant.

| **هشدار اتمام دارو** | شمارش باقی‌ماندهٔ هر دارو (اختیاری) که با هر تأیید «خوردم» یکی کم می‌شود؛ رسیدن به آستانهٔ ۵ واحد → بنر در «امروز» + برچسب در فهرست داروها |
| **نوشیدن آب** | شمارندهٔ لیوان‌های امروز با هدف روزانه، **نمودار ستونی ۷ روزه** و **یادآوری اختیاری** هر ۱/۲/۳ ساعت بین ۸ صبح تا ۱۰ شب |

### حریم خصوصی و اینترنت

- **پیش‌فرض کاملاً آفلاین:** بدون فعال‌سازی دستیار، برنامه حتی یک بایت هم به اینترنت نمی‌فرستد؛ مجوز `INTERNET` فقط برای دستیار opt-in گذاشته شده و همهٔ داده‌ها محلی می‌مانند.
- **دستیار فقط opt-in:** اینترنت تنها زمانی استفاده می‌شود که **خودتان دستیار را فعال کنید** (بدون هیچ ورودی کلید از سوی کاربر)؛ در این حالت فقط **جمع‌بندی آمار خلاصه‌شده** (تعداد نوبت‌های خورده‌شده، میانگین شاخص‌های سلامت و…) همراه با پیام شما ارسال می‌شود — **نه نام داروها، نه اطلاعات هویتی**.
- **بدون حساب و سرور:** درخواست‌ها مستقیم از دستگاه به `api.x.ai` می‌روند؛ هیچ سرور واسطی در کار نیست.
- **کلید سازنده:** کلید API داخل `lib/features/ai/ai_config.dart` قرار می‌گیرد و همراهٔ هر ساخت منتشر می‌شود؛ برای کاهش ریسک سوءاستفاده در کنسول xAI حتماً **Spend Cap** (سقف مصرف) فعال و کلید را دوره‌ای تعویض کنید (راهنما در همان فایل).
- **بدون بک‌آپ سیستم:** `android:allowBackup="false"` تا دیتابیس و گزارش‌ها بدون اجازهٔ شما روی Google Drive بک‌آپ نروند؛ بکاپ فقط دستی و آگاهانه از داخل خود برنامه (دکمهٔ «امروز») گرفته می‌شود.
- **بدون واسط:** پایگاه‌دادهٔ `darooyar.db` در پوشهٔ دادهٔ خود برنامه می‌ماند و خروجی PDF و بکاپ در پوشهٔ `darooyar_reports/` داخل «اسناد» ذخیره می‌شوند.
- **نوتیفیکیشن‌های بی‌نام:** روی قفل‌صفحه فقط وضعیت یادآوری دیده می‌شود، نه نام و دوز دارو.
- داده‌های سلامتی خانواده حتی در اختیار توسعه‌دهنده هم قرار نمی‌گیرد.

## شروعٔ سریع

### پیش‌نیازها

- **Flutter SDK** با نسخهٔ Dart `^3.13`
- برای اندروید: Android SDK + JDK 17
- برای ویندوز: Visual Studio 2022 با کامپوننت *Desktop development with C++*

### نصب و اجرا

```bash
git clone https://github.com/ArtinNourafshar/darooyar.git
cd darooyar

flutter pub get

# ویندوز
flutter run -d windows

# اندروید (دستگاه یا شبیه‌ساز متصل)
flutter run -d android
```

هیچ متغیر محیطی سفارشی یا سرویس جانبی لازم نیست.

### کیفیت و تست

```bash
flutter analyze   # بدون هیچ خطایی
flutter test      # ۷۰ تست (منطقی + ویجت)
```

پوشش تست: ارقام و تاریخ فارسی، ساخت نوبت‌ها و وضعیت‌ها (شامل نوبت‌های پیش از ثبت دارو)، بازه‌ها و آمار گزارش + **گروه‌بندی ستون‌های نمودار** (ساعت/روز/ماه شمسی)، یکتایی شناسه‌های نوتیفیکیشن (دارو، وعده، چرت، کپی‌های ۷ روزهٔ ویندوز، یادآور آب)، منطق **استریک روزهای پیاپی** و تست‌های ویجت پوسته (راست‌چین، تم مات، ناوبری ۶بخشی، ریل دسکتاپ ۷مقصدی، باز شدن صفحهٔ افراد).

### ساخت خروجی ریلیز

```bash
# اندروید → build/app/outputs/flutter-apk/app-release.apk
flutter build apk --release

# ویندوز → build/windows/x64/runner/Release/
flutter build windows --release
```

نسخه‌های منتشرشده (exe تک‌فایل ویندوز و APK اندروید) در بخش [Releases](../../releases) قرار می‌گیرند.

### نکات فنی

- **پایگاه‌داده:** حذف فرد یا دارو با `ON DELETE CASCADE` سوابق مرتبط را پاک می‌کند؛ کلید یکتای نوبت `(medication_id, log_date, log_time)` با `ConflictAlgorithm.replace` است تا تأیید مجدد، وضعیت قبلی را جایگزین کند.
- **تاریخ:** ذخیره به‌صورت میلادی `yyyy-MM-dd` و تبدیل به شمسی فقط هنگام نمایش — محاسبات بازهٔ گزارش‌ها ساده و بدون ابهام می‌ماند.
- **نوبت روز ثبت:** ساعت دقیق ثبت دارو (`created_time`) ذخیره می‌شود تا دارویی که ساعت ۱۵ ثبت شده، نوبت ۰۸ همان روز را «مصرف نشده» نبیند و درصد پایبندی خراب نشود.
- **گزارش:** بازهٔ «همهٔ تاریخچه» حداکثر ۳۶۵ روز است و جدول با رندر تنبل (`SliverList.builder`) ساخته می‌شود تا سال‌ها داده هم کرش نکند.
- **نیمه‌شب:** نوبت‌هایی که از بیست‌چهار رد می‌شوند در ساخت نوبت‌های روز لحاظ شده‌اند.
- **PDF:** جدول برعکسِ چیده می‌شود (تاریخ در سمت راست) و هر صفحه ۲۲ ردیف دارد.
- **زنگ ساعتی:** هر یادآوری یک نوتیفیکیشن زنگ‌دار با یکی از **سه صدای انتخابی** است (WLC `alarm_beep/2/3.wav` در `android/app/src/main/res/raw/` و پرست‌های `alarm1/2/3` در ویندوز؛ در اندروید هر صدا کانال جدا دارد تا صدای انتخابی روی همهٔ زنگ‌ها اعمال شود)؛ اندروید با `exactAllowWhileIdle` و full-screen intent درست در ساعت مقرر زنگ می‌زند و ویندوز چون زمان‌بندی تکی دارد، برای ۷ روز آینده کپی‌های جدا می‌سازد. همهٔ شناسه‌ها در فضاهای جدا (دارو / وعده / درون‌برنامه / چرت / آب / کپی روز) اند تا لغو یکی، دیگری را خراب نکند — پوشش‌داده‌شده با تست.
- **استریک:** `StreakCalculator` (منطق خالص، جدا از دیتابیس) نوبت‌های ۶۰ روز اخیر را روزبه‌روز بازسازی می‌کند؛ روزهای بدون نوبت (مثل پیش از ثبت دارو) نادیده گرفته می‌شوند و یک نوبت «مصرف نشده» یا «نخوردم» صفرشان می‌کند — پوشش‌داده‌شده با تست.
- **باقی‌ماندهٔ دارو:** ستون `remaining_doses` (اختیاری) با هر «خوردم» تازه یکی کم می‌شود (`consumeOne` با شرط `> 0` تا منفی نشود)؛ آستانهٔ هشدار روی ۵ واحد است.
- **آب:** جدول `water_logs` بدون کلید خارجی؛ یادآوری‌ها با شناسهٔ بازهٔ ۳۰ میلیونی و `matchDateTimeComponents.time` روزانه تکرار می‌شوند و با هر تغییر تنظیم، زمان‌بندی کامل بازسازی می‌شود.
- **بکاپ:** فایل JSON با برچسب `app: darooyar` و جدول‌ها جدا (ستون‌های ناشناخته هنگام بازیابی حذف می‌شوند)؛ بازیابی داخل یک تراکنش، همهٔ ردیف‌ها را جایگزین می‌کند و سپس پرووایدرها به‌ترتیب بارگذاری می‌شوند تا زمان‌بندی زنگ‌ها با دادهٔ جدید ساخته شود.
- **دستیار:** کلید و مدل در `lib/features/ai/ai_config.dart` ثبت می‌شوند؛ کاربر نهایی فقط دکمهٔ «فعال‌سازی دستیار» را می‌زند و هیچ کلیدی وارد نمی‌کند. بررسی روزانهٔ سلامت تنها پس از فعال‌سازی و یک‌بار در روز اجرا می‌شود و خلاصهٔ ارسالی فقط آمار عددی خلاصه‌شده است.
- **رسپانسیو:** `MediaQuery.withClampedTextScaling` با محدودهٔ ۰٫۸–۱٫۸ و شکستنی از Compact (زیر ۶۰۰) تا Extended (بالای ۱۱۰۰).

## راهنمای سازنده: دریافت کلید Grok (xAI)

برای اینکه بخش «دستیار» برای عموم کار کند، سازنده یک بار کلید می‌سازد و در `lib/features/ai/ai_config.dart` قرار می‌دهد:

1. **ثبت‌نام رایگان** در [console.x.ai](https://console.x.ai) (ایمیل + تأیید).
2. از منوی سمت چپ، **API Keys** → **Create API Key**؛ کلید (`xai-…`) فقط **یک بار** نمایش داده می‌شود؛ فوراً کپی کنید.
3. سربرگ **Billing** → افزودن اعتبار (پرداخت به ازای مصرف، بدون اشتراک). ارزان‌ترین مدل‌ها حدود ۰٫۲ تا ۱٫۲۵ دلار به ازای هر میلیون توکن‌اند (چت روزانهٔ یک کاربر معمولاً کسری از سنت در ماه هزینه دارد).
4. **حتماً Spend Cap** (سقف مصرف) مثلاً ۵ دلار در ماه تنظیم کنید و کلید را دوره‌ای تعویض کنید — کلید داخل باینری عمومی قابل استخراج است.
5. کلید را در `kGrokApiKey` و در صورت نیاز مدل را در `kGrokDefaultModel` بگذارید و اپ را بسازید. تا وقتی کلید خالی باشد، بخش دستیار پیام «کلید تنظیم نشده» نشان می‌دهد و چیزی ارسال نمی‌شود.
